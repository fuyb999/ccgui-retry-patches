# CC GUI v0.5.2 Tool-Result Title Design

## Context

Structured Codex history represents tool outputs as user-shaped messages whose
display content is `[tool_result]`. The WebView hides those carrier messages in
the transcript, but its fallback session-title calculation scans user messages
without applying the same classification. When a bounded or restored message
window begins with a tool result, the visible session label becomes
`[tool_result]` instead of a real prompt.

Local history inspection confirms that `[tool_result]` is not stored as a
Codex `user_message` or persisted custom title. The defect is confined to the
WebView's derived-title path.

## Design

- Reuse `isToolResultOnlyUserMessage` from `utils/turnScope` when scanning title
  candidates.
- Skip both the literal placeholder and structured raw messages carrying a
  `tool_result` block.
- Continue preferring a custom title and keep all existing metadata/XML filters.
- Fall back to the localized new-session label when no real prompt exists.
- Do not change history records, tool rendering, Java tab-status suffixes, or
  Codex fork/retry state.

## Verification

- A WebView hook regression test starts the message window with a structured
  `[tool_result]` carrier followed by a real prompt and requires the prompt to
  become the session title.
- The versioned patch workflow requires both the filter call and regression
  test to remain in the `v0.5.2` patch.
- Full WebView, bridge, Gradle, packaging, checksum, and artifact verification
  run before publishing `0.5.2-retry.7`.

## Release

The fix is published as `dist/ccgui-0.5.2-retry.7.zip`. Existing artifacts,
including `retry.6`, remain unchanged.
