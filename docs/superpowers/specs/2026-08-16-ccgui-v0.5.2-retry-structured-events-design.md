# CC GUI v0.5.2 Retry Structured Events Design

## Problem

The `0.5.2-retry.2` plugin keeps one logical WebView stream open while a
transient Codex failure is retried. After a retry or an automatic compaction
continuation, Codex can keep writing `reasoning`, `function_call`, and
`function_call_output` records to the session JSONL while the public SDK event
iterator remains quiet. The bridge currently scans JSONL only after an SDK
event arrives. During such quiet periods the WebView receives neither thinking
deltas nor tool blocks, although assistant text can still appear when a later
SDK message event is delivered.

Runtime evidence from the affected session established that the post-retry
call IDs are new and that the installed bridge and WebView match the tracked
`retry.2` sources. This excludes stale packaging and persistent-ID suppression
as root causes.

## Goals

- Surface post-retry thinking, tool calls, and tool results while the SDK event
  iterator is otherwise idle.
- Preserve one logical stream and the existing assistant text accumulator.
- Preserve the 10-minute upstream inactivity timeout and 30-second retry delay.
- Deduplicate events delivered by both the SDK and JSONL replay paths.
- Publish the change as `0.5.2-retry.3` without overwriting `retry.2`.

## Non-Goals

- Change which HTTP or transport failures are retryable.
- Replay assistant text from JSONL; the SDK remains authoritative for text.
- Add user-configurable polling or retry settings.
- Change Java or WebView message rendering unless a regression test proves a
  separate loss after the Node bridge emits the structured event.
- Install the new plugin or restart IDEA automatically.

## Architecture

### Polling the Session Without Masking Inactivity

`message-service.js` wraps the SDK event iterator with a polling iterator. It
keeps one pending `iterator.next()` operation and yields an internal
`session.poll` event once per second until that operation resolves. The
10-minute inactivity watchdog remains attached to the original pending
`iterator.next()` promise. Poll ticks therefore trigger local JSONL scans but
do not count as upstream activity and cannot prevent inactivity retry.

The poll delay is abortable and is cleared whenever a real SDK event, stream
completion, cancellation, or timeout wins the race. The iterator's existing
`return()` cleanup remains in place.

### Structured JSONL Replay

`codex-event-handler.js` handles `session.poll` by locating the verified
current-turn boundary and scanning new JSONL records from independent cursors:

- function and custom-tool records continue through the existing function
  replay path and retain call-ID deduplication;
- completed reasoning summaries are converted into the existing thinking
  delta and thinking-block protocol;
- assistant message records are deliberately ignored to avoid duplicating SDK
  text deltas.

The replay boundary must still be established by a `turn_context` at or after
the pre-attempt baseline. Historical session records are never eligible.

### Cross-Source Reasoning Deduplication

Reasoning may arrive first from either the SDK or JSONL. The event state tracks
the last emitted reasoning snapshot in addition to the existing per-item cache.
An identical snapshot from the other source is suppressed. A prefix extension
emits only its appended suffix, while unrelated reasoning starts a new thinking
segment using the existing full-block message path.

Tool deduplication continues to use stable call IDs. Attempt-local retry flags
are reset as before; logical output and deduplication state remain shared across
attempts so already displayed events are not replayed.

## Error Handling

- A missing session file or an unverified current-turn boundary makes a poll a
  no-op and retains the existing one-time warning behavior.
- Malformed JSONL lines are skipped.
- Reasoning records without a non-empty summary are ignored.
- Polling errors propagate through the same retry coordinator only when they
  represent a real stream failure; ordinary missing or incomplete session data
  does not fail the turn.
- Cancellation stops both the pending SDK read and the current poll delay.

## Testing

- A Node regression test starts a silent SDK iterator, appends current-turn
  reasoning and function records to a temporary JSONL file, and proves a poll
  exposes thinking, tool use, and tool result before any later SDK event.
- A timing test proves repeated poll ticks do not reset the 10-minute
  inactivity deadline.
- A deduplication test delivers the same reasoning through JSONL and then the
  SDK and proves only one visible delta is emitted.
- Existing retry classification, daily-limit, stream lifecycle, session replay,
  Java, WebView, and packaging tests must remain green.
- Artifact verification must validate the `retry.3` version, embedded Node
  polling markers, embedded WebView retry UI, ZIP checksum, and tracked patch.

## Packaging

The patched plugin version becomes `0.5.2-retry.3`. The upstream source pin
remains CC GUI `v0.5.2` at commit
`077cccff6707c11796fb0fbd3445b66abd97f83e`. The version-specific patch remains
`patches/v0.5.2/0001-codex-infinite-retry.patch`, regenerated against that pin.

The build produces and tracks:

- `dist/ccgui-0.5.2-retry.3.zip`
- `dist/ccgui-0.5.2-retry.3.zip.sha256`

Existing `retry.1` and `retry.2` artifacts remain unchanged.

## Acceptance Criteria

1. Thinking and tool blocks appear within approximately one poll interval when
   JSONL advances while the SDK iterator is idle.
2. A later SDK copy of the same reasoning or tool event is not duplicated.
3. Local poll ticks do not postpone the 10-minute inactivity retry.
4. HTTP 400, 401, 403, and daily-limit 429 remain terminal; transient 429,
   capacity, network failures, inactivity, and 5xx remain infinitely retryable
   at 30-second intervals.
5. The full verification workflow and artifact checks pass for
   `0.5.2-retry.3`.
