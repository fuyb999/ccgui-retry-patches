# CC GUI v0.5.2 Visible Retry Status Design

## Problem

The patched Codex bridge retries transient failures, but retry progress is
rendered at the end of the scrollable message list. In long conversations or
while the user is reviewing earlier messages, the progress can be outside the
viewport and appear to be missing. The current plugin also retains the upstream
`0.5.2` version, so IDEA cannot clearly distinguish the patched artifact from
the upstream release.

## Goals

- Keep active Codex retry progress visible regardless of message scroll
  position.
- Preserve the existing retry policy and sanitized retry protocol.
- Return to ordinary loading as soon as real current-turn activity arrives.
- Give the patched plugin an identifiable version and track its distribution
  artifact in Git.

## Non-Goals

- Add retry configuration controls.
- Change the 30-second retry interval or 10-minute inactivity timeout.
- Retry terminal HTTP 400, 401, 403, or daily-limit 429 responses.
- Display arbitrary upstream error messages in the WebView.

## UI Design

`ChatScreen` renders a single retry status strip directly above the input area
whenever `retryState` is non-null. The strip is outside the scrollable message
container, so it remains visible while the user scrolls through conversation
history.

The existing `WaitingIndicator` remains responsible for formatting retry
states and maintaining the countdown timer. It gains a compact retry-status
presentation suitable for the fixed strip. The message list continues to show
the ordinary loading indicator only when no retry state is active, preventing
duplicate retry displays.

The status strip presents:

- scheduled retry: retry number, allowlisted reason, and live countdown;
- started retry: retry number and a running/waiting state;
- initial Codex attempt: ordinary loading behavior rather than a retry warning.

Text wraps within the tool-window width, and the status strip has stable
padding and borders without card-style nesting.

## State Flow

The existing `[CODEX_RETRY]` protocol remains unchanged. Java validates and
forwards the sanitized payload through `onCodexRetryState`. The WebView stores
it in `MessagesContext` and sets loading to true.

`ChatScreen` reads `retryState` from that context. A scheduled retry or a
positive `attempt_started` count activates the fixed strip. Real current-turn
text, thinking, tool activity, stream completion, terminal errors, session
transitions, and explicit message clearing continue to clear retry state using
the existing callback rules.

The initial `attempt_started` payload with `retryCount: 0` uses the existing
in-list loading indicator. This avoids showing a retry warning before a retry
has actually occurred.

## Packaging

The patched plugin version becomes `0.5.2-retry.2`, while the manifest still
pins and verifies upstream CC GUI `v0.5.2` at commit
`077cccff6707c11796fb0fbd3445b66abd97f83e`. The artifact is named
`ccgui-0.5.2-retry.2.zip`.

Both the ZIP and its SHA-256 file are force-added despite the repository's
general `/dist/` ignore rule. The verification script must additionally prove
that the embedded WebView contains retry UI markers, not only that the embedded
Node bridge contains retry files.

## Testing

- Component tests prove positive retry states render in the fixed strip and
  are not duplicated in the message list.
- Component tests prove initial loading and non-retry loading retain the
  existing in-list presentation.
- Existing callback tests continue to cover sanitized payload parsing and
  state clearing.
- Workflow tests require the `retry.2` artifact name and patched plugin version.
- Artifact verification checks checksum integrity, the embedded bridge, the
  plugin version, and retry markers in the embedded WebView HTML.
- The full Node, WebView, TypeScript, Gradle, and plugin build suites run before
  publishing the artifact.

## Acceptance Criteria

1. A retrying Codex turn remains visible above the input while message history
   is scrolled away from the bottom.
2. Only allowlisted retry category, HTTP status, and code fields are displayed.
3. Success restores ordinary loading and terminal errors leave the retry UI.
4. IDEA reports the installed plugin as `0.5.2-retry.2`.
5. `dist/ccgui-0.5.2-retry.2.zip` and its checksum are tracked on `main`.
