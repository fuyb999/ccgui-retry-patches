# CC GUI v0.5.2 Canonical Session Title Design

## Context

The chat header currently derives its fallback title from the first eligible
user message in the WebView's `messages` array and then replaces everything
after 15 characters with `...`. That array is only a bounded transport window:
long live conversations send the final 180 messages, and restored Codex history
initially sends the most recent 30 user turns. Its first user message can
therefore be a later question rather than the conversation's original question.

The same truncated value is passed to the title editor. The editor then applies
a second 50-character limit, and the title persistence service rejects values
over 50 characters. Once any of these transformations runs, the WebView cannot
recover or display the complete title.

## Requirements

- The automatic/default title is the complete first real user question in the
  conversation, never a later question from a retained message tail.
- Tool results, metadata, command caveats, injected instruction blocks, empty
  messages, and internal XML carriers cannot become the first question.
- A non-empty manually edited or AI-generated title continues to override the
  automatic title.
- Title data is never shortened by adding `...` and is not silently truncated
  while editing or persisting it.
- The compact header may visually elide text according to available width.
- Hovering the displayed header title exposes its complete value in a tooltip.
- Entering edit mode loads the complete value, including titles longer than the
  former 15- and 50-character limits.

## Architecture

### Canonical first-question state

Add a session-scoped `firstUserPrompt` value beside `customSessionTitle` in the
WebView session context. Reset it synchronously whenever a new session is
created or another history session is selected. It is immutable for that
session: later message snapshots and pagination may fill an empty value, but
must never replace a non-empty value.

The header title uses this precedence:

1. Non-empty manual or AI-generated title.
2. Canonical `firstUserPrompt`.
3. The localized new-session label.

Do not scan the current visible message window as a fallback. Showing the
new-session label briefly is preferable to assigning a later question as the
conversation title.

### Live message transport

The Java streaming coalescer still has the complete session message list before
it chooses full or tail transport. Extract the first real user prompt from that
complete list and send it as optional metadata with both `updateMessages` and
`updateMessageTail`.

The extraction rules must match the existing frontend title filters. The value
is normalized for display whitespace but otherwise remains complete. The early
WebView callback placeholder must buffer this metadata together with its
message payload so a snapshot arriving before React initialization does not
lose the title.

### Restored Codex history

`HistoryMessageInjector.scanCodexHistoryPage` already scans every raw record to
construct a bounded page. Capture the first real user prompt during that full
scan, independently of the selected 30-turn page, and include it in the page
metadata sent to the WebView. The frontend accepts it only for the active
session/page, preserving the existing stale-page guards.

This avoids enlarging every history-list row with a potentially long prompt and
does not require loading the first message into the visible transcript.
Persisted manual or AI titles retain precedence when the session opens.

### Complete editing and tooltip behavior

Return the complete selected title from `useChatComputations`; remove its
15-character substring operation. Remove the editor's 50-character `maxLength`
and save-time slice, and allow the title service to persist the submitted title
without a separate 50-character rejection.

Keep `white-space: nowrap`, `overflow: hidden`, and `text-overflow: ellipsis` on
the non-editing header element. Give that element a shrinking flex width and a
native `title` attribute containing the complete string. The native tooltip is
not clipped by the header's overflow boundary and requires no duplicate popup
state. The edit input always initializes from the same complete string.

## Error Handling

- Missing or malformed first-question metadata is ignored; it cannot clear an
  existing canonical value or explicit title.
- Metadata from a stale session transition or history page is discarded with
  the corresponding message payload.
- A conversation with no eligible user prompt keeps the localized new-session
  label.
- Persistence failures continue through the existing title-update error path;
  the UI must not truncate the title as a hidden recovery behavior.

## Verification

- A hook test proves a complete canonical first prompt wins even when the
  visible window begins with a later question, while explicit titles still win.
- A coalescer test proves a long first snapshot carries the original user prompt
  alongside the bounded tail and ignores metadata/tool-result carriers.
- A Codex history pagination test proves the first prompt is retained when the
  visible page contains only recent turns.
- Callback tests prove title metadata survives early initialization, obeys
  sequence/session guards, and cannot be replaced by later snapshots.
- A header component test proves the tooltip and edit input contain the complete
  value and saving a title over 50 characters does not shorten it.
- A title-service test proves values over 50 characters persist unchanged.
- Focused tests, the full WebView and Java suites, the Gradle plugin build, patch
  replay, ZIP contents, and checksum are verified before publication.
