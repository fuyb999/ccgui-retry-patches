# CC GUI v0.5.2 Visible Retry Status Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and track a `0.5.2-retry.2` CC GUI plugin whose active Codex retry status remains visible above the input area regardless of message scroll position.

**Architecture:** Keep the existing sanitized `[CODEX_RETRY]` protocol and `MessagesContext` state. Add a focused WebView status-strip component outside the scrollable message container, suppress the duplicate in-list retry indicator, and preserve ordinary initial loading. Extend the versioned build manifest and artifact verifier so IDEA identifies the patched version and verification proves both the embedded bridge and WebView contain retry support.

**Tech Stack:** JavaScript/Node.js, React 19, TypeScript, Vitest, Less, Java 17, Gradle IntelliJ Plugin, Bash, Git patches, ZIP/SHA-256 verification.

- [ ] **Step 4: Implement the minimal status-strip component**

Create the component with the existing context type and indicator:

```tsx
import type { CodexRetryState } from '../contexts/MessagesContext';
import { WaitingIndicator } from './WaitingIndicator';

interface RetryStatusStripProps {
  retryState?: CodexRetryState | null;
}

export const RetryStatusStrip = ({ retryState }: RetryStatusStripProps) => {
  if (!retryState || retryState.retryCount < 1) return null;
  return (
    <div className="codex-retry-status" role="status" aria-live="polite">
      <WaitingIndicator retryState={retryState} variant="status" />
    </div>
  );
};
```

Add `variant?: 'inline' | 'status'` to `WaitingIndicatorProps`, default it to
`'inline'`, and add the variant as a modifier class without changing retry
text or countdown behavior:

```tsx
<div className={`waiting-indicator waiting-indicator--${variant}`}>
```

Render `<RetryStatusStrip retryState={retryState} />` in `ChatScreen`
immediately after `.messages-shell` and before `ScrollControl`. In
`MessageList`, render the in-list indicator only for ordinary or initial
loading:

```tsx
{loading && (!retryState || retryState.retryCount === 0) && (
  <WaitingIndicator startTime={loadingStartTime ?? undefined} retryState={retryState} />
)}
```
