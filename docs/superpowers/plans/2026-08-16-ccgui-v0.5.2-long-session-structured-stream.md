# CC GUI v0.5.2 Long-Session Structured Stream Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `0.5.2-retry.4`, which keeps current-turn thinking and tool blocks visible when the mutable assistant message falls outside the bounded 180-message transport tail.

**Architecture:** Extend the existing Java tail selection with one optional sparse assistant anchor containing the omitted message and its absolute backend index. Send the anchor in the same sequenced `updateMessageTail` invocation, then let the WebView patch it only when that backend index is addressable before applying the ordinary tail merge and existing message normalization.

**Tech Stack:** Java 17, JUnit 4, IntelliJ JCEF bridge, React 19, TypeScript 5.9, Vitest 3, Gradle, Bash patch workflow.

- [ ] **Step 3: Add sparse-anchor selection**

Extend the transport record and locate only the global last assistant omitted by a valid tail update:

```java
record MessageTransport(
        List<ClaudeSession.Message> messages,
        int baseIndex,
        boolean tailUpdate,
        ClaudeSession.Message anchorMessage,
        int anchorIndex
) {}

private static int findLastAssistantIndex(List<ClaudeSession.Message> messages) {
    for (int index = messages.size() - 1; index >= 0; index--) {
        if (messages.get(index).type == ClaudeSession.Message.Type.ASSISTANT) {
            return index;
        }
    }
    return -1;
}
```

In `selectMessageTransport`, set the anchor only when `tailUpdate` is true and the last assistant index is less than `baseIndex`; otherwise use `null` and `-1`.

- [ ] **Step 4: Parse the optional anchor independently from the tail**

Extend `processMessageTail` with the same optional arguments. After parsing a valid tail, parse the anchor in its own guarded block so any failure leaves `anchorMessage` null and does not escape the outer tail handler:

```ts
let anchorMessage: ClaudeMessage | null = null;
const anchorIndex = typeof assistantAnchorIndex === 'number'
  ? assistantAnchorIndex
  : Number(assistantAnchorIndex);
if (
  typeof assistantAnchorJson === 'string' &&
  Number.isSafeInteger(anchorIndex) &&
  anchorIndex >= 0 &&
  anchorIndex < baseIndex
) {
  try {
    const parsedAnchor = JSON.parse(assistantAnchorJson) as unknown;
    if (
      Array.isArray(parsedAnchor) &&
      parsedAnchor.length === 1 &&
      parsedAnchor[0]?.type === 'assistant'
    ) {
      anchorMessage = parsedAnchor[0] as ClaudeMessage;
    }
  } catch {
    anchorMessage = null;
  }
}
```

- [ ] **Step 5: Patch the addressable backend slot before the normal tail merge**

Use `currentBaseIndex` and the prepended-history offset to calculate the local index. Require the current slot to exist and already be an assistant before replacing it:

```ts
let current = prev;
if (anchorMessage && Number.isSafeInteger(anchorIndex)) {
  const localAnchorIndex = prependedCount + anchorIndex - currentBaseIndex;
  const backendEndIndex = prependedCount + backendMessageCount;
  if (
    localAnchorIndex >= prependedCount &&
    localAnchorIndex < backendEndIndex &&
    current[localAnchorIndex]?.type === 'assistant'
  ) {
    current = [...current];
    current[localAnchorIndex] = anchorMessage;
  }
}

const prependedHistory = prependedCount > 0
  ? current.slice(0, prependedCount)
  : [];
let merged = hasFullPrefix
  ? [...current.slice(0, prependedCount + baseIndex), ...tail]
  : [...prependedHistory, ...tail];
```
